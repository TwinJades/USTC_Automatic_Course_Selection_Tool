## 路线二

### 3.0.0

- 路线二增加共享核心、Windows 目录包和 Linux x86_64 目录包候选；Windows 保留 WebView2，Linux SSH 服务使用纯 HTTP 认证，支持人工短信和图形验证码交互。
- 候选包移除 Playwright、Chromium、Node 和独立更新器；Windows 仅含桌面依赖，Linux 仅含 CLI 依赖。更新分别复用桌面主程序和 CLI 的辅助模式，保留目录替换、握手与失败恢复。
- Linux 更新进程身份使用 `/proc` 原始启动时钟，避免 .NET 跨进程时间换算误差导致父进程及服务身份被误拒绝。
- CLI JSON 输出直接显示中文；认证失败增加脱敏 HTTP 状态、页面类型、认证方式和学校数字错误码，不输出凭据或原始页面。
- 认证字段解析改用 HTML 解析器；普通短信入口继承本人本次输入的学校账号，group 使用学校提供的绑定号码。短信密钥和风控字段按本页开关条件提交，不复用旧密钥；覆盖无密钥普通短信与带风控 group 的回归。
- 精简 HTTP 认证：密码和短信表单按页面风控开关决定是否携带风控字段；移除每次认证步骤前的接口加密配置探测和页面结构调试摘要，失败信息保留阶段、HTTP 状态和学校数字错误码。
- 短信页缺少 `login-croypto` 时按官方前端方式继续：不再拒登，改为不携带风控字段提交；对应回归改为“缺密钥仍创建人工挑战且可完成短信登录”。
- 修复新登录挑战沿用上一轮图形验证码的问题：每次建立挑战会清空旧验证码与“已发送”标志；图形码校验失败也立即作废，避免用旧图重复提交。
- 图形验证码改取短信子系统按账号绑定的端点（`POST /sso-extend/protected/api/aggregate/sms/publicNoToken/generate`，body `{phone,type:"DEFAULT"}`）。通用 `captcha/generate` 生成的码不被发送接口接受，是此前固定 `2180000` 的原因。
- 增加包内数据路径、Windows 首次旧数据迁移、Linux systemd 服务和系统加密凭据，以及基于北京时间的监测、预约与授权恢复。目录式更新及恢复按平台分别维护。
- 源码版本升级为 3.0.0。已在东京 Ubuntu 26.04 VPS 用真实账号完成一次 HTTP 登录（密码 → 短信页 → 绑定式图形码 → 短信码 → 只读身份核对，得到本人学号），当时无开放轮次；本次只更新源码，未创建标签或发布 GitHub Release 附件。加密凭据保存、不同版本在线更新和 2 核 2 GB 性能仍未验收。
