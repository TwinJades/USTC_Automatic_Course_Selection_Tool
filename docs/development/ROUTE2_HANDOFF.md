## 2. 用户的最终目标

为中国科学技术大学综合教务系统制作 Windows 单机选课助手。程序运行在个人 Windows 电脑上，用户可配置多个教学班代码和优先级；在有余量时自动选课；必要时退掉用户明确配置的冲突旧课，选新课失败时尝试恢复旧课。

用户的优先级：**隐私安全 > 稳定性 > 易用性 > 抢课速度**。

## 3. 已确认的需求与安全边界

### 登录与隐私

- 首次登录、短信验证、新设备验证必须由用户本人在程序内置登录窗口完成。
- 不得绕过短信、验证码、平台风控或访问限制。
- 用户希望可选地保存账号和密码，并在会话失效后尝试自动登录。
- 密码不得写入 JSON、日志、源代码或普通文本文件；应使用 Windows Credential Manager 保存。
- 自动登录遇到短信/新设备验证时必须停止并提示用户操作，认证完成后才恢复。
- 软件无服务器、无云同步、无用户账户；课程配置与日志只存本机。

### 课程任务

- 教学班以完整课程代码唯一标识，例如 `001683EX.01`。
- 可同时监测多门课；优先级数字越小越先处理。
- 同一轮内，已选的高优先级课程只移除与其冲突的低优先级待选任务。
- 冲突旧课可以有多门，使用课程代码列表配置。
- 退课 → 选新课 → 失败恢复旧课不是原子交换；恢复失败时必须停止任务并强提醒。
- 发现“时间冲突”或“同课程代码只能选一门”时，自动取消该任务的“启用”。
- 不使用候补/选课申请功能。

### 运行方式

- Windows 10/11 x64；最终用户不应安装 Python、Node.js 或 .NET。
- 支持 5 秒、15 秒、60 秒、自定义检查间隔，以及用户可选的每周期 `±1/3` 随机抖动。
- 支持运行时段、开机自动启动（默认关闭）、本地日志保留 14 天；用户已明确取消“仅工作日”。
- 笔记本合盖要持续运行，需要用户自行在 Windows 电源设置中设置“合盖时不采取任何操作”。

## 4. 路线一的实现与已知限制

路线一使用 WPF + WebView2，在同一内置浏览器中登录后以 DOM 操作完成：切换标签、输入课程代码、读页面文本、点击选课/退课按钮、识别并关闭弹窗。

路线一的主要限制：

- 多门课需要逐门切换/搜索，检查轮次耗时随任务数增长。
- 教务前端异步刷新、页面结构/弹窗变化可能造成旧容量或状态误判。
- 选退课结果判断依赖页面文字和 DOM，维护成本较高。

路线二的目的就是替换“读取数据与提交选退课”的底层方式；可复用路线一的任务、优先级、冲突回滚、日志、运行时段和 UI 设计，但不要直接修改路线一工程。

## 5. 路线二的定义

路线二不是坐标点击，也不是绕过认证。它应当：

1. 继续使用内置 WebView2，让用户手动完成统一身份认证与短信验证；
2. 从**已认证的本机 WebView2 会话**安全复制当前会话 Cookie/必要请求上下文到独立 HTTP 请求层；
3. 调用教务网页前端自身使用的内部请求，批量读取数据并串行提交选退课；
4. 会话失效时回到内置窗口认证，而不是自行绕过认证。

相对路线一，路线二应减少前端页面切换、批量获取课程数据、得到结构化返回结果；但它依赖未公开的内部接口，必须做兼容性验证和回退设计。

其中记录的内部请求包括：

| 功能 | 路径/动作 |
| --- | --- |
| 开放选课轮次 | `POST /ws/for-std/course-select/open-turns` |
| 已选教学班 | `POST /ws/for-std/course-select/selected-lessons` |
| 可选教学班 | `POST /ws/for-std/course-select/addable-lessons` |
| 批量人数 | `POST /ws/for-std/course-select/std-count`，传 `lessonIds[]` |
| 选课 | `POST /ws/for-std/course-select/add-request` |
| 退课 | `POST /ws/for-std/course-select/drop-request` |
| 查询选退课结果 | `POST /ws/for-std/course-select/add-drop-response` |

旧库中的请求字段可作为起点：

- `turnId`、`studentId`
- `courseSelectTurnAssoc`、`studentAssoc`、`lessonAssoc`
- `requestId`

### 不可照搬的部分

- `CASClient.login_by_pwd()` 采用旧 CAS 密码提交流程，假设 `captcha_payload` 为空；用户已反馈它最近登录有问题。路线二**不得依赖或修复这条自动登录流程作为首选认证方式**。
- `save_token()` 将登录令牌写入普通 JSON 文件，不符合当前安全要求。
- `add-drop-response` 的轮询循环没有等待间隔；不得照搬，以免高频请求。
- 示例会并发尝试多门课；选退课及冲突恢复必须串行。

## 7. 推荐开发阶段

### 阶段 A：项目隔离与会话桥接（无选课动作）

- 新建独立路线二项目；不改路线一源码。
- 使用 WebView2 `CookieManager` 或等效机制读取已认证会话所需 Cookie；不得把 Cookie/密码写入日志。
- 新建 `HttpClient`/`CookieContainer`，带必要的 `Origin`、`Referer`、User-Agent 等正常网页上下文。
- 明确认证失效判定和重新认证流程。

验收：用户手动登录后，路线二只读请求可确认当前选课轮次和内部学生编号。

### 阶段 B：只读影子验证（无选课动作）

- 读取 `selected-lessons`、`addable-lessons`、`std-count`。
- 将路线二读到的课程代码、名称、人数/上限与内置网页当前显示对比。
- 支持一批目标课的容量查询，不允许提交选课、退课请求。
- 接口错误仅写脱敏日志，自动回退/提示用户继续使用路线一。

验收：连续多次对比，结构化数据与网页显示一致；确认高峰期和会话失效时的行为。

### 阶段 C：单门受控操作验证

- 只允许用户明确指定的测试教学班。
- 调用 `add-request`/`drop-request` 后以服务器的 `add-drop-response` 为准。
- 结果轮询应有限次数、带合理等待与退避；禁止无间隔忙轮询。
- 每次成功/失败后再读取 `selected-lessons` 核验最终状态。

验收：成功、人数已满、时间冲突、同代码冲突、认证失效分别得到准确状态，且无重复提交。

### 阶段 D：完整任务引擎

- 复用路线一的任务/优先级/冲突恢复语义，但新建路线二的数据模型或共享库副本。
- “退旧课 → 选新课 → 恢复旧课”严格串行。
- 多门独立目标课可以按优先级依次处理，但不得并发选退课。
- 保留路线一为可选择的回退执行模式；路线二接口异常时暂停，不得盲目切换状态。

### 阶段 E：安全的可选自动登录

- 账号可保存到普通配置；密码仅写入 Windows Credential Manager。
- 首选：用户已认证的 WebView2 会话持续复用。
- 会话失效后，可尝试在正常登录表单中填写保存在凭据管理器内的账号密码。
- 一旦要求短信/新设备认证，立即停止自动提交并让用户本人继续。
- 不读取、不存储验证码、短信内容或认证令牌到普通文件。

## 8. 非功能性要求

- 所有可执行程序以语义化版本号发布；路线二建议从 `2.0.0-alpha.1` 开始，不能覆盖 `1.0.0`。
- 每次发布生成单独目录，例如 `release/2.0.0-alpha.1/`。
- 文档、日志、界面均明确当前使用“路线一/路线二”。
- 任何删除旧版本文件前，必须说明会绕过回收站还是移动到可恢复归档，不得无提示永久删除。
- 正式版用户不需要安装开发环境。
